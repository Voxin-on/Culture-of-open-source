## 1. Локальный запуск с 127.0.0.1

Два сервиса запущены на 1 компе поэтому order может обращаться к product просто через http://127.0.0.1:8001

## 2. Неудачный запуск контейнера с 127.0.0.1

Тут сервисы живут в разных контейнерах и тут 127.0.0.1 значит сообственный контейнер а не соседа к которому идёт обращение из за этого All connection attempts failed

## 3. Успешное взаимодействие через имена сервисов

Если контейнеры в 1 docker сети то они могут обращаться просто через имена  например http://product-service:8000

## 4. host.docker.internal

Когда из контейнера надо получить что то на локальном компе 127.0.0.1 не поможет т.к. это сам контейнер но есть специальный адрес host.docker.internal который указывает на локальный комп
